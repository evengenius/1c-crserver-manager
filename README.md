Управление сервером хранилища конфигураций 1С (1c-crserver-manager)
1c-crserver-manager — это инструмент (набор скриптов), предназначенный для автоматизации и упрощения администрирования сервера хранилища конфигураций 1С:Предприятие (crserver) на серверах под управлением ОС Linux.

Скрипт решает главную проблему штатной поставки 1С под Linux: отсутствие удобных инструментов "из коробки" для быстрого развертывания, управления несколькими службами хранилищ, настройки автозапуска и резервного копирования.

🌟 Ключевые возможности
Управление службами (systemd): Автоматическая генерация и регистрация systemd-юнитов для серверов хранилища.

Мультисерверность: Возможность запуска нескольких изолированных экземпляров crserver на одном сервере (на разных портах и с разными каталогами данных).

Простое развертывание: Быстрое создание новых хранилищ конфигураций одной командой.

Управление жизненным циклом: Удобный запуск, остановка, перезагрузка и проверка статуса служб хранилища.

Резервное копирование: Встроенные (или легко интегрируемые) механизмы для создания бекапов файлов хранилища.

Управление правами: Автоматическая установка правильных прав доступа к директориям хранилища (обычно для пользователя usr1cv8).

📋 Системные требования
ОС: Linux (Debian, Ubuntu, CentOS, RHEL, Ред ОС, Astra Linux и др., использующие systemd).

Установленная платформа 1С:Предприятие: Должны быть установлены пакеты сервера 1С (в частности, исполняемый файл crserver).

Права: Для установки и управления системными службами требуются права суперпользователя (root или sudo).

🛠 Установка
Клонирование репозитория:

Bash
git clone https://github.com/evengenius/1c-crserver-manager.git
cd 1c-crserver-manager
Настройка прав на исполнение:
Убедитесь, что главный скрипт имеет права на выполнение:

Bash
chmod +x crserver-manager.sh
Конфигурация (при необходимости):
Отредактируйте конфигурационный файл (например, .conf или переменные внутри скрипта), чтобы указать:

Путь к бинарным файлам 1С (зависит от версии, например /opt/1cv8/x86_64/8.3.22.1923/).

Базовый каталог, где будут храниться данные хранилищ (например, /var/1c/crserver/).

🚀 Использование (Примеры команд)
Примечание: Синтаксис команд может незначительно отличаться в зависимости от текущей версии скрипта. Ниже приведены типичные паттерны использования.

1. Создание нового хранилища
Создает директорию для хранилища, устанавливает права и генерирует службу.

Bash
sudo ./crserver-manager.sh create --name "my_repo" --port 1542
--name — имя хранилища (будет использоваться как имя службы и папки).

--port — TCP-порт, на котором будет слушать crserver.

2. Запуск и остановка хранилища
Так как скрипт интегрируется с systemd, управление можно осуществлять как через сам менеджер, так и стандартными командами Linux:

Bash
# Через скрипт:
sudo ./crserver-manager.sh start "my_repo"
sudo ./crserver-manager.sh stop "my_repo"

# Или через systemctl:
sudo systemctl start crserver-my_repo
sudo systemctl stop crserver-my_repo
3. Проверка статуса
Позволяет вывести список всех настроенных хранилищ и их текущее состояние (Работает/Остановлено).

Bash
sudo ./crserver-manager.sh status
4. Удаление хранилища
Останавливает службу, удаляет systemd-юнит. (Внимание: обычно скрипты не удаляют сами данные хранилища в целях безопасности, это нужно сделать вручную).

Bash
sudo ./crserver-manager.sh remove "my_repo"
⚙️ Внутреннее устройство работы
При выполнении команды создания хранилища, скрипт выполняет следующие действия:

Ищет директорию с актуальной версией 1С (утилиту crserver).

Создает папку для нового хранилища по пути, указанному в настройках.

Меняет владельца папки на пользователя 1С (обычно usr1cv8:grp1cv8).

Генерирует файл /etc/systemd/system/crserver-<ИМЯ>.service. В файле прописываются аргументы запуска crserver, такие как порт -port и путь к данным -d.

Выполняет systemctl daemon-reload и, опционально, systemctl enable для автозапуска при старте ОС.

🛡 Рекомендации по безопасности и эксплуатации
Порты: Убедитесь, что порты, выделяемые для хранилищ (например, 1542, 1543 и т.д.), открыты в межсетевом экране (iptables/firewalld) для разработчиков.

Бекапы: Хранилище 1С — это файловая база данных. Рекомендуется настроить ежедневное копирование директорий хранилищ в архив, предварительно останавливая соответствующую службу crserver, чтобы избежать повреждения данных во время копирования.

Обновление платформы: При обновлении версии платформы 1С потребуется изменить пути к бинарным файлам в конфигурации скрипта и пересоздать/обновить службы (systemd юниты).
