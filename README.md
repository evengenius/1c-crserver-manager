# 1c-crserver-manager

**1c-crserver-manager** — bash-скрипт для автоматизации развёртывания и администрирования сервера хранилища конфигураций 1С:Предприятие (`crserver`) на Linux. Включает интерактивное меню, CLI-команды, управление несколькими установленными версиями платформы, файрвол, бэкапы и самообновление из репозитория.

Текущая версия: **1.2.0**

---

## Возможности

- **Полная установка одной командой** — система зависимостей, локаль, пользователь `usr1cv8`, systemd-служба, файрвол, запуск.
- **Несколько версий платформы 1С** на одной машине — установка/удаление/переключение активной версии без переустановки.
- **Управление службой** — старт/стоп/рестарт/статус/логи через единый интерфейс.
- **Файрвол (iptables)** — белый список IP/подсетей, режим «открыто всем», корректная вставка правил, сохранение через `netfilter-persistent`.
- **Бэкап и восстановление** хранилищ — ручной/автоматический (cron), хранение N дней, удаление по номеру или возрасту.
- **Диагностика** — проверка бинарника, службы, порта, прав, локали, диска одной командой.
- **Самообновление** — `update`, `update --check`, `update --force` тянет последнюю версию скрипта прямо из GitHub.
- **Безопасный парсер конфига** (без `source`) — защита от инъекций команд через `/etc/1c-crserver/crserver.conf`.

## Системные требования

- **ОС:** Debian 12 / Ubuntu 22.04+ (других дистрибутивов скрипт не тестировался — отдельные команды специфичны для apt/dpkg/systemd).
- **Зависимости:** `bash 4+`, `systemd`, `iptables`, `curl` (нужен для `update`), стандартные утилиты coreutils.
- **Права:** root или sudo.
- **Пакеты 1С** для целевой версии — четыре `.deb`: `common`, `server`, `ws`, `crs` (без `nls`).

## Установка

```bash
git clone https://github.com/evengenius/1c-crserver-manager.git
cd 1c-crserver-manager
chmod +x crserver-manager.sh
sudo ./crserver-manager.sh
```

Опционально — добавить в `PATH`, чтобы вызывать как `crserver`:

```bash
sudo ./crserver-manager.sh path-install
# теперь работает: sudo crserver
```

Скрипт создаст симлинк `/usr/local/bin/crserver` на исходный файл.

## Подготовка пакетов 1С

Дистрибутив 1С нужно положить в каталог `packages/<версия>/` рядом со скриптом:

```
crserver-manager.sh
packages/
├── 8.3.25.1560/
│   ├── 1c-enterprise-8.3.25.1560-common_*.deb
│   ├── 1c-enterprise-8.3.25.1560-server_*.deb
│   ├── 1c-enterprise-8.3.25.1560-ws_*.deb
│   └── 1c-enterprise-8.3.25.1560-crs_*.deb
└── 8.3.27.2130/
    └── ...
```

Пакеты `*-nls-*` (локализации) скрипт игнорирует. Можно использовать пункт меню **«Импорт пакетов»** (или подменю «Управление версиями» → 4) — скрипт сам разложит `.deb` из произвольного каталога по подкаталогам с правильным именем версии.

## Использование

### Интерактивный режим

```bash
sudo ./crserver-manager.sh
```

Главное меню:

```
1) Управление версиями        — установка/удаление/переключение версий 1С
2) Управление службой         — start/stop/restart, статус, логи
3) Настройки сервера          — порт, каталог хранилищ, регенерация юнита
4) Управление доступом        — iptables: разрешённые IP, белый список
5) Бэкап и восстановление     — ручной/cron, восстановление из архива
6) Инструменты                — info, проверка порта, диск, диагностика
7) Быстрый вызов (PATH)       — установка/удаление симлинка
8) Обновление скрипта         — проверка и установка новой версии
9) Справка
```

### CLI-команды

| Команда | Назначение |
|---|---|
| `sudo crserver` | Интерактивное меню |
| `sudo crserver install` | Полная установка (выбор версии из `packages/`) |
| `sudo crserver uninstall` | Полное удаление (с подтверждением `DELETE`) |
| `sudo crserver start` / `stop` / `restart` | Управление службой |
| `sudo crserver status` | Статус службы и порта |
| `sudo crserver logs` | Последние 50 строк журнала |
| `sudo crserver backup` | Создать бэкап хранилищ |
| `sudo crserver diagnose` | Диагностика конфигурации |
| `sudo crserver versions` | Показать активную/установленные/доступные версии |
| `sudo crserver path-install` / `path-remove` | Симлинк в `/usr/local/bin` |
| `sudo crserver update` | Обновить скрипт из GitHub |
| `sudo crserver update --check` | Проверить наличие обновлений без установки |
| `sudo crserver update --force` | Принудительно перезаписать любую версию |
| `sudo crserver version` | Показать текущую версию скрипта |
| `sudo crserver help` | Справка |

## Самообновление

Скрипт умеет тянуть свежую версию прямо из репозитория:

```bash
sudo crserver update
```

Что происходит:
1. Скачивается актуальный `crserver-manager.sh` с `raw.githubusercontent.com`.
2. Проверяется синтаксис (`bash -n`) — битый файл не будет применён.
3. Сравнивается версия (`SCRIPT_VERSION`) — если уже актуальная, ничего не делает (либо `--force`).
4. Делается резервная копия рядом: `crserver-manager.sh.bak.<timestamp>`.
5. Атомарная замена через `mv`, права сохраняются.

После обновления нужно перезапустить скрипт вручную — он сам не делает `exec`, чтобы не оборвать текущее меню.

### Если установлена очень старая версия (без команды `update`)

Обновитесь однократно вручную (пример для типичной установки в `/root/`):

```bash
sudo curl -fsSL -o /tmp/crsm.new \
    https://raw.githubusercontent.com/evengenius/1c-crserver-manager/main/crserver-manager.sh \
  && sudo bash -n /tmp/crsm.new \
  && sudo cp -p /root/crserver-manager.sh /root/crserver-manager.sh.bak.$(date +%Y%m%d_%H%M%S) \
  && sudo mv /tmp/crsm.new /root/crserver-manager.sh \
  && sudo chmod +x /root/crserver-manager.sh \
  && grep '^SCRIPT_VERSION=' /root/crserver-manager.sh
```

## Управление несколькими версиями

Сценарий «обновить платформу 1С на сервере» теперь без боли:

1. Положить новый дистрибутив в `packages/8.3.27.2130/` (или импортировать через меню).
2. Меню → Управление версиями → **Установить версию** → выбрать новую.
3. Меню → Управление версиями → **Переключить активную версию** → выбрать новую.

Скрипт остановит службу, дождётся освобождения порта (до 15 секунд, при необходимости — `pkill`), пересоздаст systemd-юнит с новым бинарником, запустит и проверит, что порт слушается. При ошибке выведет последние строки `journalctl`.

Старую версию можно удалить отдельным пунктом меню — если удаляется активная и есть другая установленная, скрипт автоматически переключится на неё.

## Файрвол

Меню «Управление доступом» работает с iptables-цепочкой `CRSERVER`. Модель цепочки:

```
1. ACCEPT loopback
2..N-1. ACCEPT для разрешённых IP/подсетей
N. финальное правило: ACCEPT (открытый режим) или DROP (белый список)
```

Новые IP всегда вставляются **перед** финальным правилом — не блокируются по ошибке. Переключение между «открыто всем» и «белый список» — отдельные пункты меню. Правила сохраняются через `netfilter-persistent` (если установлен).

Удаление правила по номеру использует **настоящие iptables-номера** (показываются в `[N]` рядом с правилом).

## Бэкапы

- **Ручной**: меню → 5 → 1, либо `sudo crserver backup`. Создаётся `tar.gz` в `BACKUP_DIR` (по умолчанию `/var/1c/backup`).
- **Восстановление**: меню → 5 → 2. Служба останавливается, архив распаковывается с проверкой ошибок, права чинятся, служба запускается обратно.
- **Cron**: меню → 5 → 3. Создаёт `/usr/local/bin/crserver-backup.sh`, добавляет задачу в `crontab` (03:00 ежедневно), хранит N дней (запрашивается). Ошибки бэкапа пишутся в `logger -t crserver-backup` и в `.last-backup.log` рядом.
- **Удаление**: по возрасту (`-mtime`) или по номеру в списке.

## Конфигурация

Конфиг лежит в `/etc/1c-crserver/crserver.conf`:

```
REPO_DIR="/var/1c/repo"
REPO_PORT="1542"
LOG_DIR="/var/log/1c/crserver"
BACKUP_DIR="/var/1c/backup"
```

Изменения через меню «Настройки сервера» — конфиг сохраняется автоматически и systemd-юнит регенерируется. Прямое редактирование файла тоже поддерживается: значения парсятся безопасным построчным парсером (никакого `source`), посторонние ключи игнорируются.

## Подключение из конфигуратора 1С

После установки сервер слушает на `tcp://<IP>:<PORT>/` (по умолчанию порт 1542). В конфигураторе:

```
Конфигурация → Хранилище конфигурации → Подключиться к хранилищу
Адрес: tcp://IP_СЕРВЕРА:1542/имя_хранилища
```

`IP_СЕРВЕРА` подскажет меню «Информация о системе» и пункт «Список хранилищ» (он же покажет все существующие хранилища и готовые URL для подключения).

## Диагностика проблем

```bash
sudo crserver diagnose
```

Проверяет: наличие бинарника `crserver`, установленные версии, файл systemd-юнита, активность службы, прослушивание порта, права на каталог хранилищ, локаль `ru_RU.UTF-8`, занятость диска. Выводит сводку «X проблем обнаружено».

Если служба не стартует:
```bash
sudo journalctl -u crserver -n 50
```

## Безопасность

- Конфиг не выполняется как код (не `source`, а парсер с whitelist ключей).
- Правила iptables не содержат пользовательский ввод без валидации.
- IP/подсети валидируются регулярными выражениями.
- Самообновление проверяет HTTP-код, синтаксис скачанного файла и делает бэкап перед заменой.

## Откат после неудачного обновления скрипта

Бэкап создаётся автоматически рядом с исходным файлом:

```bash
sudo mv /root/crserver-manager.sh.bak.YYYYMMDD_HHMMSS /root/crserver-manager.sh
```

## Известные ограничения

- Только Debian-based дистрибутивы (apt/dpkg).
- Только iptables (не nftables напрямую — но через `iptables-nft` shim в Debian 12 работает).
- `crserver` запускается с `Type=simple` — для сборок 1С, требующих явного daemon-режима, юнит может потребовать корректировки.
