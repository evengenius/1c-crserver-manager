# 1c-crserver-manager

**1c-crserver-manager** — bash-скрипт для автоматизации развёртывания и администрирования сервера хранилища конфигураций 1С:Предприятие (`crserver`) на Linux. **Поддерживает несколько независимых инстансов** на одном сервере: каждый со своей версией платформы, своим портом и каталогом хранилищ. Включает интерактивное меню, CLI-команды, файрвол, бэкапы и самообновление из репозитория.

Текущая версия: **2.0.3** (мульти-инстанс)

> **Если вы обновляетесь с v1.x**: установка станет **multi-instance** автоматически. Меню «Инстансы → Миграция со старой установки» предложит безопасно перенести существующий `crserver.service` в инстанс с именем `default` (с переносом каталога хранилищ). Простой ~10 секунд.

---

## Зачем нужны инстансы

Один сервер `crserver` обслуживает один формат хранилища. Если у вас часть проектов на платформе 8.3.25, часть на 8.3.30 — раньше пришлось бы держать две машины или регулярно переключать версию. С v2.0.0 это решается одной командой:

```
Инстанс 'prod25':  crserver 8.3.25 на порту 1542 → /var/1c/repo-prod25
Инстанс 'dev30':   crserver 8.3.30 на порту 1543 → /var/1c/repo-dev30
```

Оба работают одновременно, не мешая друг другу. Миграция проекта со старой версии на новую — бэкап в одном инстансе, восстановление в другом, обновление формата конфигуратором, удаление в исходном.

## Возможности

- **Мульти-инстанс архитектура** — несколько `crserver@<имя>.service` через systemd-template, каждый со своей версией платформы, портом, каталогом хранилищ и логов.
- **Полная установка одной командой** — система зависимостей, локаль, пользователь `usr1cv8`, шаблон `crserver@.service`, файрвол, первый инстанс.
- **Несколько версий платформы 1С** — разные инстансы могут использовать разные `/opt/1cv8/x86_64/<version>/`.
- **Хранилища конфигураций** — на инстанс: список, подготовка, переименование, удаление, бэкап/восстановление одного хранилища, проверка целостности.
- **Файрвол (iptables)** — общая цепочка `CRSERVER` на все инстансы + опциональная индивидуальная `CRSERVER-<имя>` для отдельных IP конкретного инстанса.
- **Бэкап и восстановление** — на инстанс. Имена архивов: `<инстанс>_<ts>.tar.gz` (полный) и `<инстанс>_repo_<имя>_<ts>.tar.gz` (одно хранилище).
- **Диагностика** — на инстанс: бинарник, служба, порт, права, локаль, диск.
- **Самообновление** — `update`, `update --check`, `update --force`. Обходит CDN-кэш GitHub, корректно работает через симлинки.
- **Безопасный парсер конфига** (без `source`) — защита от инъекций.
- **Автомиграция** — старые v1.x установки переводятся в инстанс `default` с переносом данных.

## Системные требования

- **ОС:** Debian 12 / Ubuntu 22.04+ (другие дистрибутивы не тестировались).
- **Зависимости:** `bash 4+`, `systemd`, `iptables`, `curl` (для `update`).
- **Права:** root или sudo.
- **Пакеты 1С** для целевой версии — четыре `.deb`: `common`, `server`, `ws`, `crs`.

## Установка

```bash
git clone https://github.com/evengenius/1c-crserver-manager.git
cd 1c-crserver-manager
chmod +x crserver-manager.sh
sudo ./crserver-manager.sh
```

Опционально — добавить в `PATH`:

```bash
sudo ./crserver-manager.sh path-install
# теперь работает: sudo crserver
```

## Подготовка пакетов 1С

Дистрибутив кладётся в `packages/<версия>/` рядом со скриптом:

```
packages/
├── 8.3.25.1560/
│   ├── 1c-enterprise-8.3.25.1560-common_*.deb
│   ├── 1c-enterprise-8.3.25.1560-server_*.deb
│   ├── 1c-enterprise-8.3.25.1560-ws_*.deb
│   └── 1c-enterprise-8.3.25.1560-crs_*.deb
└── 8.3.30.0000/
    └── ...
```

NLS-пакеты игнорируются. Пункт меню «Импорт пакетов» разложит `.deb` из произвольного каталога автоматически.

## Главное меню

```
═══════════════════════════════════════════
  Сервер хранилища 1С:Предприятие   v2.0.0
  Инстансы: prod25* [running]  dev30 [stopped]   (* — по умолчанию)
  Платформы: 8.3.25.1560 8.3.30.0000
═══════════════════════════════════════════

 1) Управление версиями (1С платформы)
 2) Инстансы                          ← создать/удалить/настроить, миграция
 3) Управление службами               ← start/stop/logs, выбор инстанса
 4) Хранилища конфигураций            ← на инстанс
 5) Файрвол                           ← общий + индивидуальный
 6) Бэкап и восстановление            ← на инстанс
 7) Инструменты                       ← диагностика
 8) Быстрый вызов (PATH)
 9) Обновление скрипта
10) Справка
```

Если инстанс **один** — пункты 3/4/6 работают с ним молча. Если **несколько** — спрашивают «выберите инстанс», с подсказкой про инстанс по умолчанию (Enter).

## Меню «Инстансы»

```
1) Список инстансов (статус, версия, порт, размер)
2) Создать инстанс
3) Настроить инстанс (порт, версия, каталоги)
4) Удалить инстанс (опционально с данными)
5) Сделать инстанс по умолчанию
6) Информация об инстансе
7) Миграция со старой установки (если есть crserver.service)
0) Назад
```

При создании инстанса:
- **Имя** — `^[a-z][a-z0-9-]{0,31}$` (например `prod`, `dev30`, `migration-q2`).
- **Версия** — выбирается из установленных платформ.
- **Порт** — проверяется на занятость через `ss -tln`.
- **Каталоги** — дефолты `/var/1c/repo-<имя>/`, `/var/log/1c/<имя>/`, можно переопределить.

Конфиг инстанса лежит в `/etc/1c-crserver/instances/<имя>.conf`, юнит создаётся как `crserver@<имя>.service` через шаблон.

## CLI

### Универсальные команды (на default-инстансе или единственном)

```bash
sudo crserver                          # интерактивное меню
sudo crserver install                  # первый инстанс
sudo crserver start | stop | restart | status | logs
sudo crserver backup                   # полный бэкап инстанса
sudo crserver diagnose
sudo crserver versions                 # установленные платформы
sudo crserver path-install | path-remove
sudo crserver update [--check | --force]
sudo crserver version
sudo crserver help
```

### Выбор инстанса для конкретной команды

```bash
sudo crserver -i dev30 start
sudo crserver -i dev30 logs
sudo crserver -i dev30 status
sudo crserver -i dev30 backup
sudo crserver -i dev30 repo backup proj_x
```

Если инстансов больше одного и не задан default, команды без `-i` выдадут ошибку с подсказкой. Опция `-i <имя>` принимается в любой позиции (`crserver -i prod25 start` ≡ `crserver start -i prod25`).

### Управление инстансами

```bash
sudo crserver instance list
sudo crserver instance create <имя> --version <V> --port <P> [--repo-dir D] [--log-dir L]
sudo crserver instance delete <имя> [--purge-data]
sudo crserver instance set-default <имя>
sudo crserver instance start <имя> | stop | restart | status | logs
```

### Хранилища (на выбранном инстансе)

```bash
sudo crserver -i dev30 repo list
sudo crserver -i dev30 repo info trade_dev
sudo crserver -i dev30 repo create trade_dev
sudo crserver -i dev30 repo rename trade_dev trade_prod
sudo crserver -i dev30 repo backup trade_dev
sudo crserver -i dev30 repo restore trade_dev          # последний бэкап с этим именем
sudo crserver -i dev30 repo restore /var/1c/backup/dev30_repo_trade_dev_20260101_120000.tar.gz
sudo crserver -i dev30 repo delete trade_dev
```

> Бэкапы (полный инстанс, отдельное хранилище, cron) автоматически проходят `tar -tzf`-проверку целостности после создания. Битый архив удаляется и фиксируется в логе.

## Сценарий миграции проекта между версиями платформы

Допустим, есть инстансы `prod25` (8.3.25) и `dev30` (8.3.30), нужно перенести проект `trade` с 25-й на 30-ю:

```bash
sudo crserver -i prod25 repo backup trade
# архив: /var/1c/backup/prod25_repo_trade_20260101_120000.tar.gz

# В меню «Хранилища» на dev30 → «Восстановить»: выбрать архив prod25_repo_trade_*.
# Конфигуратор подключаем к dev30, открываем хранилище — он предложит обновить формат.
# После успеха:
sudo crserver -i prod25 repo delete trade
```

Простой проекта — на время бэкапа и переключения клиентов на новый URL.

## Самообновление

```bash
sudo crserver update           # с подтверждением
sudo crserver update --check   # только проверить
sudo crserver update --force   # перезаписать любую версию
```

Что делает: скачивает свежий скрипт через `raw.githubusercontent.com` (с обходом CDN-кэша), проверяет синтаксис (`bash -n`), сравнивает версии, делает бэкап текущего файла рядом (`*.bak.<ts>`), атомарно заменяет через `mv`. Если запущен через симлинк — обновляет реальный файл.

После обновления нужно перезапустить скрипт вручную.

## Файрвол

Меню «Файрвол» работает с двумя уровнями цепочек:

- **Общая** `CRSERVER` — whitelist на все порты всех инстансов. Loopback всегда разрешён, политика по умолчанию — `ACCEPT` (открыто всем) или `DROP` (только разрешённые IP).
- **Индивидуальная** `CRSERVER-<имя>` — дополнительные ACCEPT-правила, привязанные к порту конкретного инстанса.

При создании инстанса в `INPUT` добавляется правило `--dport <порт> -j CRSERVER`, при удалении — убирается.

## Бэкапы

- **Полный бэкап инстанса**: меню «Бэкап» → 1, либо `crserver backup` / `crserver -i <имя> backup`. Архив `<инстанс>_<ts>.tar.gz`.
- **Бэкап одного хранилища**: меню «Хранилища» → 6, либо `crserver -i <имя> repo backup <имя_хранилища>`. Архив `<инстанс>_repo_<хранилище>_<ts>.tar.gz`.
- **Восстановление**: меню «Бэкап» → 2 (или меню «Хранилища» → 7 для одного хранилища). Существующие данные сохраняются как `.pre-restore.<ts>` для отката.
- **Cron**: меню «Бэкап» → 3. Создаёт `/usr/local/bin/crserver-backup-<инстанс>.sh` и задачу в `crontab` (03:00 ежедневно).
- **Удаление старых бэкапов**: по возрасту или по номеру в меню.

## Конфигурация

```
/etc/1c-crserver/
├── instances/
│   ├── prod25.conf            # NAME/VERSION/REPO_DIR/REPO_PORT/LOG_DIR
│   └── dev30.conf
├── default-instance           # имя инстанса по умолчанию (одна строка)
└── crserver.conf.legacy       # переименованный старый конфиг (после миграции)
```

```
/etc/systemd/system/
└── crserver@.service          # шаблон для всех инстансов
```

Прямое редактирование `instances/*.conf` поддерживается — используется безопасный построчный парсер с whitelist ключей. После правки запустить `systemctl restart crserver@<имя>`.

## Подключение из конфигуратора 1С

```
Конфигурация → Хранилище конфигурации → Подключиться к хранилищу
Адрес: tcp://IP_СЕРВЕРА:<порт_инстанса>/имя_хранилища
```

Адреса инстансов и список хранилищ показывает меню «Хранилища».

## Диагностика проблем

```bash
sudo crserver diagnose                  # на default
sudo crserver -i dev30 diagnose         # на конкретном
```

Проверяет: бинарник `crserver` инстанса, файл юнита, активность службы, порт, права на каталог, локаль, занятость диска. Отдельно сообщает о «фантомной» версии (юнит ссылается на удалённый бинарник) и предлагает автофикс.

Если служба не стартует:
```bash
sudo journalctl -u crserver@<имя> -n 50
```

## Безопасность

- Конфиги не выполняются как код (парсер с whitelist ключей).
- Имена инстансов и хранилищ валидируются регулярными выражениями.
- IP/подсети валидируются перед добавлением в iptables.
- Самообновление: проверка HTTP-кода, синтаксиса скачанного файла, бэкап перед заменой.
- Пользователь службы — `usr1cv8`, не root.

## Откат после неудачного обновления скрипта

```bash
sudo mv /root/crserver-manager.sh.bak.YYYYMMDD_HHMMSS /root/crserver-manager.sh
```

## Известные ограничения

- Только Debian-based дистрибутивы (apt/dpkg).
- Только iptables (через `iptables-nft` shim в Debian 12 работает).
- `crserver` запускается с `Type=simple` и `ProtectSystem=full` — для систем со строгой systemd-политикой может потребоваться корректировка.
