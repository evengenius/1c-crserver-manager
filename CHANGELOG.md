## [2.0.3] — 2026-04-25

### Безопасность операций
- `do_repo_backup`, `do_backup`, CLI `repo backup` обрабатывают SIGINT/SIGTERM:
  Ctrl+C во время `tar -czf` больше не оставляет недописанный архив на диске.
- `move_dir_safe` проверяет свободное место на целевой ФС через `df` перед
  копированием на другую файловую систему. Раньше копирование могло начаться
  и оборваться на середине, оставив частичный каталог.
- `get_legacy_install` возвращает 1, если в обнаруженном legacy-юните не
  удалось распарсить версию платформы. Повреждённая v1.x-установка больше
  не воспринимается как «обнаруженная» и не предлагается к миграции.

### UX
- При создании инстанса проверяется не только коллизия портов с другими
  инстансами, но и реальная занятость порта в системе через `ss -tlnH`.
- Понижение версии в `do_instance_edit` (`8.3.30 → 8.3.25`) требует явного
  подтверждения с предупреждением: после обновления формата хранилища
  конфигуратором понижение делает данные нечитаемыми.
- Опция `-i/--instance` принимается в любой позиции аргументов CLI:
  `crserver start -i dev30` теперь равнозначно `crserver -i dev30 start`.

### CLI / автоматизация
- `update --check` всегда возвращает exit 0 при успешном выполнении проверки
  (включая «уже актуальная версия»), и exit 1 только при сетевой/парсинговой
  ошибке. Раньше код 1 в обоих случаях сбивал cron-обёртки. Внутренние коды
  100/101 сохранены для интерактивного использования из меню.

## [2.0.2] — 2026-04-25

### Файрвол
- `chain_rule_count` всегда печатает число (awk-обёртка вместо
  `grep -c | true`). Раньше при пустой цепочке возвращалась пустая строка,
  и `add_allowed_ip` фолбэчил на ветку `-A`, нарушая порядок правил.
- `setup_firewall_chain` больше не сбрасывает существующую цепочку: при
  пересоздании инстанса whitelist-настройки администратора сохраняются.
- Per-instance цепочка валидирует имя через `instance_name_valid` и
  проверяет лимит iptables (28 символов) — раньше длинное имя инстанса
  ронял `iptables -N`.

### Валидация
- `instance_save` запрещает совпадение `REPO_DIR` и `LOG_DIR`, а также
  вложенность одного в другой: защита от `chown -R` и `rm -rf` на одном
  каталоге.
- Введён `version_name_valid` (`^8\.3\.[0-9]+\.[0-9]+$`), применяемый везде,
  где имя версии становится частью пути. Защита от path traversal в
  `/opt/1cv8/x86_64/<ver>/` и `packages/<ver>/`.

### Установка пакетов
- `install_version` ставит четыре `.deb` одной командой `apt-get install`:
  apt разруливает порядок и подтягивает зависимости (`libwebkit2gtk` и др.).
  Раньше серия `dpkg -i` падала на первой ошибке зависимостей. Старый путь
  (`dpkg -i` + `apt-get install -f`) сохранён как fallback.

### Прочее
- `do_full_uninstall` обёрнут в `set +e` вокруг цикла удаления инстансов:
  uninstall дочистит остальные инстансы даже если `awk`/`systemctl` упадёт
  на одном из них.
- `do_repo_check` явно проверяет `[[ -d "$dir" ]]` перед `stat`/`find`.
- ss-проверки порта переведены с `grep ":port"` на `awk` по 4-й колонке
  с якорем `$`. Раньше для порта 1542 матчились и 15420, 15425.
- В cron-скрипте бэкапа: `KEEP_DAYS` закавычен, как и `+${KEEP_DAYS}` в `find -mtime`.

## [2.0.1] — 2026-04-25

### Критические фиксы
- `do_instance_delete`: `cleanup_instance_chain` теперь вызывается **до**
  `rm -f conf` (и в меню, и в CLI). Функция читает порт из конфига через
  `awk` — при удалении конфига **до** очистки файрвола, per-instance
  цепочка оставалась прицепленной к `INPUT`.
- `do_repo_restore`: проверяется, что в архиве **ровно один** top-level
  каталог с допустимым именем хранилища. Раньше при несовпадении имён
  rollback мог оставить «осиротевший» pre-restore-каталог.
- CLI `repo delete`: `was_active`-логика отделена от exit-кода `rm -rf`.
  Если `rm` падал, служба больше не возвращалась под `set -e`. Добавлена
  валидация имени.

### Новое в CLI
- `repo info <имя>` — машинно-читаемая сводка по хранилищу.
- `repo rename <старое> <новое>` — переименование с остановкой/запуском службы.
- `repo restore <архив | имя_хранилища>` — восстановление по полному пути
  к архиву или по имени хранилища (берётся свежайший бэкап в `BACKUP_DIR`).

### Целостность бэкапов
- После `tar -czf` в `do_repo_backup`, `do_backup`, CLI `repo backup` и
  cron-скрипте выполняется `tar -tzf` для проверки целостности.
  Битый архив удаляется немедленно с записью в лог.

## [2.0.0] — мульти-инстанс архитектура

Полная переработка архитектуры. Один сервер обслуживает несколько независимых
инстансов через systemd-template `crserver@<имя>.service`. Каждый инстанс —
свой конфиг в `/etc/1c-crserver/instances/<имя>.conf` (VERSION, REPO_PORT,
REPO_DIR, LOG_DIR), своя версия платформы, свои хранилища, свои бэкапы.
Файрвол: общая цепочка `CRSERVER` + опциональные `CRSERVER-<имя>` для
тонких per-instance ACL. Автомиграция со старой v1.x установки в инстанс
`default` через пункт меню «Инстансы → Миграция».
